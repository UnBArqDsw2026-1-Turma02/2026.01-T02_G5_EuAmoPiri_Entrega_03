# 3.2.4 Decorator

## Introdução

O Decorator é um padrão de projeto estrutural do catálogo GoF (Gang of Four) que permite adicionar novos comportamentos a um objeto dinamicamente, envolvendo-o em objetos chamados decoradores (ou wrappers). Esses decoradores implementam a mesma interface do objeto original, tornando-os completamente intercambiáveis do ponto de vista do código cliente.

De acordo com Gamma et al. (1994), na obra Design Patterns: Elements of Reusable Object-Oriented Software, o padrão Decorator tem como finalidade anexar responsabilidades adicionais a um objeto de maneira dinâmica, constituindo uma alternativa flexível ao uso de subclasses para a extensão de funcionalidades. Assim, sua aplicação favorece a composição de objetos, permitindo que diferentes comportamentos sejam combinados em tempo de execução sem modificar a estrutura da classe original.

## Objetivo

O Decorator tem como objetivo permitir a adição dinâmica de responsabilidades a um objeto, sem alterar sua classe original e sem recorrer à herança. Ele faz isso envolvendo o objeto em camadas de wrappers que compartilham a mesma interface, de forma que o código cliente não percebe diferença entre o objeto puro e o objeto decorado.

A solução implementa o padrão estrutural Decorator para permitir que objetos do tipo `Relato` recebam funcionalidades adicionais de forma dinâmica, sem alterar a implementação original da classe `RelatoConcreto`.

A estrutura é composta por:

- `Relato`: componente base abstrato;
- `RelatoConcreto`: implementação concreta do relato;
- `RelatoDecorator`: decorator base;
- decorators especializados:
  - `MidiaDecorator`
  - `VerificadoDecorator`
  - `DestaqueDecorator`

---

### Estrutura da Implementação

#### Componente base

A classe `Relato` representa o componente base do padrão Decorator. Ela define os atributos principais do relato e estabelece os métodos obrigatórios compartilhados entre o objeto concreto e os decorators.

```python
from abc import ABC, abstractmethod

class Relato(ABC):

    def __init__(self, nome_usuario: str, relato: str, avaliacao: int):
        self._nome_usuario = nome_usuario
        self._relato = relato
        self._avaliacao = avaliacao

    @property
    def nome_usuario(self) -> str:
        return self._nome_usuario

    @property
    def avaliacao(self) -> int:
        return self._avaliacao

    @abstractmethod
    def get_conteudo(self) -> str:
        pass

    @abstractmethod
    def editar_relato(self, novo_texto: str) -> None:
        pass

    @abstractmethod
    def excluir_relato(self) -> str:
        pass

    def __str__(self) -> str:
        return self.get_conteudo()
```

A utilização de uma classe abstrata garante que todos os objetos decorados mantenham a mesma interface.

---

#### Implementação concreta

A classe `RelatoConcreto` representa o relato original do sistema, sem funcionalidades adicionais.

```python
class RelatoConcreto(Relato):

    def get_conteudo(self) -> str:
        return (
            f"[Relato de {self._nome_usuario}] "
            f"{self._relato} "
            f"(avaliação: {self._avaliacao}/5)"
        )

    def editar_relato(self, novo_texto: str) -> None:
        self._relato = novo_texto
        print(f"Relato de '{self._nome_usuario}' editado com sucesso.")

    def excluir_relato(self) -> str:
        return f"Relato de '{self._nome_usuario}' excluído."
```

Essa classe contém o comportamento principal do relato.

---

#### Decorator base

A classe `RelatoDecorator` implementa a base estrutural do padrão Decorator.

```python
class RelatoDecorator(Relato):

    def __init__(self, relato: Relato):
        self._wrapped = relato

    @property
    def nome_usuario(self) -> str:
        return self._wrapped.nome_usuario

    @property
    def avaliacao(self) -> int:
        return self._wrapped.avaliacao

    def get_conteudo(self) -> str:
        return self._wrapped.get_conteudo()

    def editar_relato(self, novo_texto: str) -> None:
        self._wrapped.editar_relato(novo_texto)

    def excluir_relato(self) -> str:
        return self._wrapped.excluir_relato()
```

O atributo `_wrapped` armazena o objeto encapsulado, permitindo que novos comportamentos sejam adicionados dinamicamente sem alterar o objeto original.

---

#### Decorators concretos

##### MidiaDecorator

Responsável por adicionar imagens ou vídeos ao relato.

```python
class MidiaDecorator(RelatoDecorator):

    def __init__(self, relato: Relato, url_midia: str, tipo_midia: str):
        super().__init__(relato)
        self._url_midia = url_midia
        self._tipo_midia = tipo_midia

    def get_conteudo(self) -> str:
        icone = "📷" if self._tipo_midia == "imagem" else "🎥"

        return (
            f"{self._wrapped.get_conteudo()} "
            f"[{icone} {self._tipo_midia}: {self._url_midia}]"
        )
```

---

##### VerificadoDecorator

Responsável por adicionar informações de verificação ao relato.

```python
class VerificadoDecorator(RelatoDecorator):

    def __init__(self, relato: Relato, verificado_por: str):
        super().__init__(relato)
        self._verificado_por = verificado_por

    def get_conteudo(self) -> str:
        return (
            f"{self._wrapped.get_conteudo()} "
            f"[✓ Verificado por {self._verificado_por}]"
        )
```

---

##### DestaqueDecorator

Responsável por adicionar destaque e prioridade ao relato.

```python
class DestaqueDecorator(RelatoDecorator):

    def __init__(self, relato: Relato, fixado: bool = True, prioridade: int = 1):
        super().__init__(relato)
        self._fixado = fixado
        self._prioridade = prioridade

    def get_conteudo(self) -> str:

        if not self._fixado:
            return self._wrapped.get_conteudo()

        return (
            f"{'⭐' * max(1, 4 - self._prioridade)} "
            f"DESTAQUE (prioridade {self._prioridade}) "
            f"{'⭐' * max(1, 4 - self._prioridade)}\n"
            f"{self._wrapped.get_conteudo()}"
        )
```

---

### Encadeamento dos decorators

A composição dinâmica ocorre através do encapsulamento sucessivo dos objetos:

```text
DestaqueDecorator
        ↓
VerificadoDecorator
        ↓
MidiaDecorator
        ↓
RelatoConcreto
```

Cada decorator adiciona uma responsabilidade adicional ao método `get_conteudo()`, preservando a interface comum do componente base.

---

### Exemplo de uso

```python
relato = RelatoConcreto(
    nome_usuario="Carlos Turista",
    relato="O mirante tem uma vista incrível!",
    avaliacao=5
)

relato_com_midia = MidiaDecorator(
    relato,
    "foto.jpg",
    "imagem"
)

relato_verificado = VerificadoDecorator(
    relato_com_midia,
    "Ana Moradora"
)

relato_destaque = DestaqueDecorator(
    relato_verificado
)
```

## Análise da implementação

A implementação representa corretamente o padrão Decorator, pois os decorators encapsulam objetos do tipo `Relato` e adicionam funcionalidades extras sem modificar a implementação original da classe concreta.

Além disso, a solução evita a explosão de subclasses específicas, como:

- `RelatoComMidia`
- `RelatoVerificado`
- `RelatoComMidiaEDestaque`

A abordagem adotada permite combinar comportamentos dinamicamente através de composição, tornando a solução mais flexível, reutilizável e extensível.
